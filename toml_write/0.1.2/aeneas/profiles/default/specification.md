# Default profile

The crate-wide contract is in [SPECIFICATION.md](../../../SPECIFICATION.md). Both extractions select the default Cargo features on `aarch64-apple-darwin`. The [theorem inventory](theorems.json) identifies the exact audited statements and 12 public API mappings for unchanged release bodies.

- [BuilderProofs.lean](proofs/BuilderProofs.lean) checks the ten explicit selectors over arbitrary modeled builder states. Each theorem establishes successful return, exact encoding choice, and preservation of the decoded string and any returned newline field.
- [MetricsProofs.lean](proofs/MetricsProofs.lean) checks the whole key metrics scan against byte-list predicates, `TomlKeyBuilder::new` with all cached fields and the unchanged input, and their composition with `as_unquoted`. Empty keys do not qualify for unquoted encoding.
- [ValueMetricsProofs.lean](proofs/ValueMetricsProofs.lean) checks exact value metrics when every run of either quote byte has length at most 255. The scan returns the two longest run lengths and the three presence flags for value controls, backslash, and LF. `TomlStringBuilder::new` has the same run precondition and preserves the input text with these exact metrics. The independent run-length model takes the maximum of initial matching block lengths over all suffixes, so the bound applies to quotes within each contiguous run. There is no bound on total input length.
- For a run of at least 256 of either quote byte, the modeled `TomlStringBuilder::new` produces `integerOverflow`. The intermediate quote overflow statements identify each failing loop transition. This is the checked arithmetic semantics of the Aeneas model. The [native finding](../../../verification/findings/TOML-WRITE-001.md) gives separate release evidence for the checked and unchecked profiles.
- [DefaultSelectionProofs.lean](proofs/DefaultSelectionProofs.lean) checks the two adapted Rust defaults against the independent selection order, checks the ordered option-chain equations, and composes each adapted selector with the corresponding released constructor through an explicit mapping of builder fields. The string composition uses the same quote-run precondition. The two default bodies in the published release remain outside the formal extraction claim. The [source patch](patches/default-selection.patch) and [native comparison](default-selection-check.rs) give the correspondence evidence.

The unchanged-body extraction uses two local standard-library models for [Str::as_bytes and Str::is_empty](proofs/TomlWrite/FunsExternal.lean). They use identity and list emptiness over Aeneas's existing byte representation of strings. That model admits arbitrary byte lists. Rust provides valid UTF-8 and the metric observations apply to those inputs. These Rust standard-library semantics and the Rust-to-Lean correspondence are trusted. The verifier source is unchanged. The release extraction uses byte-checked release sources, and the default adaptation uses a separate, archived patch applied to an isolated copy.

The shared extractor lacks split output support. The crate-local split extraction check uses the standard Aeneas output mechanism, and the managed runner verifies source and tool identities, checks exact regeneration of both outputs, clean-builds Lean, and audits theorem kinds and transitive axioms. Native tests separately exercise default, no-default-feature, and alloc-only configurations, with a separate release/adaptation comparison.

The [boundary notes](extraction-boundaries.md) document why the original default bodies and formatting and serialization are outside the direct proof.
