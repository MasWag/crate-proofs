# Current verification result: exact byte-slice writes

The managed offline verifier **passed** on 2026-11-10 for the `default` profile on `aarch64-apple-darwin`. The accepted run is `.work/runs/default-i1smpzub`. This extends the earlier success-only byte contracts to **total success and exact output equality** for `FxHasher32::write`, `FxHasher64::write`, and native `FxHasher::write` on the supported 64-bit little-endian target.

For every represented initial state and byte slice, the generated operation returns `Result.ok` and its final state equals the unchanged independent byte specification. Empty inputs preserve the state. The proof covers all full 4-byte or 8-byte blocks, the optional 4-byte chunk in the 64-bit algorithm, and the remaining individual bytes. It adds no caller length or state-reachability restrictions. The native theorem states the exact generated cast-to-64/write64/cast-back semantics; Rust-to-model correspondence requires the already documented 64-bit width match.

The checked chain is [byte decoding](proofs/ByteDecode.lean), [equivalent specification recurrences](proofs/SpecRecurrence.lean), [generated block and tail loops](proofs/ByteFunctional.lean), and [public write contracts](proofs/WriteContracts.lean). The three public mappings now select `fxHasher32_write_exact`, `fxHasher64_write_exact`, and `fxHasher_write_exact`. Earlier success-only theorems remain as audited helpers. The accepted inventory contains **67 named theorems and 24 public API mappings**; helper counts are not additional API coverage.

The fresh run regenerated and exactly compared the maintained Lean model, cleaned and rebuilt the local Lean package, checked theorem kinds and mappings, and audited transitive dependencies. Only `propext`, `Classical.choice`, and `Quot.sound` were accepted. Pipeline and audit fingerprints each matched before and after, and the primary independently rechecked all recorded artifact digests and 70 current fingerprinted files. Native observations remain separate: the upstream release has zero unit tests/doctests, and the differential harness passed three tests in debug and three in release.

Aeneas, Charon, Rust source adaptations, generated Lean model, and the independent specification definitions were not changed for this extension. The proof still concerns the disclosed adapted Rust, with source review and finite testing supporting release correspondence; it is **not** a formal equivalence proof of adapted and unchanged release Rust. Generic `hash`/`hash32`/`hash64`, inherited Hasher methods, collection aliases and standard collection algorithms remain outside the claims. No new fxhash implementation bug was identified in this extension; the existing [README finding](../../../verification/findings/FXHASH-001.md) remains unchanged.

**Formal scope:** all 15 unsigned integer write methods across `FxHasher32`, `FxHasher64`, and native-width `FxHasher` have total-success state-update equations against the independent mixing specification. The three `Default` and three `finish` contracts are checked. All three byte-slice `Hasher::write` methods are proved to succeed for arbitrary modeled states and slices, including empty input. The actual 32/64-bit byte loops and tails are present in the generated model, and the helper proofs establish index safety, loop termination and success. They do **not** yet prove the output state equals `Spec.write32` or `Spec.write64`. Generic `hash`, `hash32`, `hash64`, collection aliases and standard collection behavior were not extracted or proved.

The final source adaptation removes those translation boundaries while preserving the stated operations on this target. The accepted formal proof does not license a broader target or release-byte claim.
