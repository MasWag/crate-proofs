## Expected behavior and its basis

Partial parsing returns a value and the number of bytes consumed. A format disallowing multiple leading zeros still permits a single zero. Accordingly, `b"0"` consumes one byte and `b"-0"` consumes two.

## Observed behavior

With `no_integer_leading_zeros(true)`, unsigned `b"0"` returns `Ok((0, 0))`; signed `b"-0"` returns `Ok((0, 1))`. Complete `b"0"` succeeds, partial `b"0!"` consumes one byte, and complete `b"01"` returns `InvalidLeadingZeros(0)` in the controls. The parser has reached the single-zero handling path; the returned count omits the zero.

## Issue-ready draft

Title: Partial parsing omits a single zero from the consumed length

## Description

`from_lexical_partial_with_options` reports too few consumed bytes for a single zero when the format forbids integer leading zeros.

## Prerequisites

- Rust version: 1.94.1
- lexical-parse-integer version: 1.0.6
- Features: `format`, `power-of-two`
- Direct dependency: `lexical-util` 1.0.7 with `format` and `power-of-two`

## Test case

```rust
use lexical_parse_integer::{FromLexicalWithOptions, Options};
use lexical_util::format::NumberFormatBuilder;

fn main() {
    const FORMAT: u128 = NumberFormatBuilder::new()
        .no_integer_leading_zeros(true).build_strict();
    let result = u8::from_lexical_partial_with_options::<FORMAT>(b"0", &Options::new());
    assert_eq!(result, Ok((0, 1))); // actual: Ok((0, 0))
}
```

## Additional Context

This also occurs with `-0`, which reports one consumed byte instead of two. Related: https://github.com/Alexhuszagh/rust-lexical/issues/225.
