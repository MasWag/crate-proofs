# UTF8-001: Manually constructed incomplete states can panic

## Identity and classification

- Crate/version: `utf-8` 0.7.6; component: release implementation
- Kind: specification question; confidence: reproduced; resolution: open
- First observed and last reproduced: 2026-11-27
- Upstream report: not reported; upstream fix: not checked

## Observation and reproduction

With `Incomplete::new(&[0x61, 0xff])` and empty input, `try_complete` panics
at the checked subtraction unwrap in `src/lib.rs:166`. Independently,
`Incomplete::new(&[0xff, 0xff])` panics at line 173. A valid incomplete
prefix `[0xe2, 0x82]` with empty input returned `None`. The latter two
observations were made by a temporary probe, retained as
`verification/reproduce-incomplete.rs` (SHA-256
`0ec9b4fbe69d6ee0b4ed0eea78647ff02b4941f7e057423fe7b9ee941cf9c1bb`).
The minimal retained reproducer below covers the first branch.

Reproducer: `verification/repro/incomplete-state.rs`, SHA-256
`f9f8c9b3a876861dde1b30e37c668390eca80e3582d7e84ca24eec8b02976834`.

## Interpretation and status

The first decoded event can end before the initial buffer length for a
manually constructed state. Both branches then unwrap a failed subtraction.
This example does not establish a failure in the documented decode-produced
state workflow. A caller can avoid these examples by passing the incomplete
suffix produced by `decode`; the exact broader permitted state domain remains
an API question. No fix has been tested or reported upstream.

The upstream repository was inspected read-only at default branch `master`,
commit `218fea2b57b0e4c3de9fa17a376fcc4a4c0d08f3`: its root has no `.github`,
contribution instructions, or legacy issue template. Searches for `Incomplete`
and `panic` found no matching issues. The repository is archived. No issue has
been filed.
