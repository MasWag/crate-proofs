# LEB128FMT-003: Fixed unsigned array encoding panics at width seven

## Identity and classification

- Component: release implementation; kind: implementation-bug; confidence: reproduced-at-pinned-inputs; resolution: open.
- Crate/version: leb128fmt/0.1.0; first observed and last reproduced: 2026-11-28; upstream report: not-reported; upstream fix: not-checked.

## Pinned inputs

`source.lock.json` SHA-256 `de198d9bfda1cf725813d9957bdd96c275cee7885d1b8f0e474be7749b345609`; release archive SHA-256 `09edd9e8b54e49e587e4f6295a7d29c3ea94d469cb40ab8ca70b288248a81db2`; `src/lib.rs` SHA-256 `d3416930498758a653a176d50658540adf1c81cd1e5eade97272b4df69ae92cc`. The maintained test instantiates `encode_fixed_uint_arr!` with `u32` and width 7.

## Expected and observed behavior

Zero is representable and its fixed-length seven-bit encoding is `[0]`. Instead the call panics at index 1 of an array of length 1. The loop's terminal shift is 7, after the only byte has already been written.

## Cause, impact and resolution
