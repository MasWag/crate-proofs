# LEB128FMT-002: Signed slice encoders accept an out-of-range value

## Identity and classification

- Component: release implementation; kind: implementation-bug; confidence: reproduced-at-pinned-inputs; resolution: open.
- Crate/version: leb128fmt/0.1.0; first observed and last reproduced: 2026-11-28; upstream report: not-reported; upstream fix: not-checked.

## Pinned inputs

`source.lock.json` SHA-256 `de198d9bfda1cf725813d9957bdd96c275cee7885d1b8f0e474be7749b345609`; release archive SHA-256 `09edd9e8b54e49e587e4f6295a7d29c3ea94d469cb40ab8ca70b288248a81db2`; `src/lib.rs` SHA-256 `d3416930498758a653a176d50658540adf1c81cd1e5eade97272b4df69ae92cc`. Both slice encoders were tested with `i16`, width 8, value 128, two-byte output and cursor 0.

## Expected and observed behavior

The signed 8-bit range is -128–127; both encoders should return `None` without writing or advancing. Both instead return `Some(2)`, write `[0x80, 0x01]`, and advance the cursor to 2. The precheck shifts by `BITS` rather than accounting for the sign bit. The same guard also accepts `encode_fixed_sint_slice::<i16, 7>(127, ...)`, although 127 is outside the signed 7-bit range; with a one-byte output it panics while attempting a second write. The retained native test catches this panic in debug and optimized builds.

## Cause, impact and resolution

The range check accepts this out-of-range value; any formal claim must account for the counterexample. No fix or upstream contact is recorded.
