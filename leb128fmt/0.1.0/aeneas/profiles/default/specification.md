# LEB128 contracts for leb128fmt 0.1.0

The reference implementation is the crates.io release identified by `source.lock.json`. The library has default feature `std`, which supplies the standard error trait implementation. The integer and byte specifications below use mathematical integers. They cover the codec families exported from `src/lib.rs`. Each entry is a proof obligation. The profile's audited theorem inventory and results identify the obligations actually discharged.

## Values and byte strings

For a positive width `w`, let `L = ⌈w/7⌉`. Unsigned values lie in `[0, 2^w)`, and signed values in `[-2^(w-1), 2^(w-1))`. Byte indices start at zero. For a string of length `k ≥ 1`, define its unsigned value by

    U(b,k) = Σ (b[i] mod 128) · 128^i, for 0 ≤ i < k.

Its signed value is `U(b,k) - 128^k` when the terminating byte's payload is at least 64, and `U(b,k)` otherwise. A complete encoding has `1 ≤ k ≤ L`, bytes at least 128 before its terminator, and a terminator below 128. Its mathematical value must be in the specified width's range. This admits padding and enforces zero or sign extension in the final partial group. Decode uses the first terminator, so later bytes may take arbitrary values.

For an in-range integer `x`, its payload digit at position `i` is the Euclidean remainder of `floor(x / 128^i)` modulo 128. A shortest unsigned encoding uses the least positive `k` with `x < 128^k`. A shortest signed encoding uses the least positive `k` with `-128^k/2 ≤ x < 128^k/2`. A fixed encoding uses `k=L`. In each case byte `i<k` is the payload digit plus 128 exactly when `i+1<k`. These formulas also determine zero, minus one, powers of 128, and each representation endpoint.

## Public operations

For each function on the indicated inputs the intended total-success theorem requires the extracted body to return `Result.ok out` with the stated observations. A Rust `None` or `Err` is a possible value of `out`. The outer Aeneas result separately accounts for computation failure and divergence.

| Release surface | Input and expected observations |

| `is_last` | On every byte, returns true exactly when its unsigned value is below 128. |
| `max_len::<BITS>` | For every Rust `u32` width whose result fits the target's `usize`, returns the ceiling of its division by seven, including zero for width zero. |
| `encode_u32`, `encode_u64`, `encode_s32`, `encode_s64` | Every input of the named integer type returns `Some((a,k))` with the shortest encoding in the first `k` bytes. Every remaining byte of the array equals zero. |

| Six exported array macros | For each expansion with a built-in integer type of matching signedness and `1 ≤ w ≤ type width`, apply the corresponding array contract at `w`. Encoders return `None` for out-of-range values. Expansion-specific obligations include all partial-group widths and multiples of seven. |
| `encode_uint_slice`, `encode_sint_slice` | Given `1 ≤ w ≤ type width`, a cursor `p` within or at the end of the buffer, and an in-range value, copy the shortest encoding from `p`. When it fits, return `Some(k)` and advance the cursor by `k`. On insufficient space return `None`, copy the prefix that fits, and preserve the cursor. On an out-of-range value return `None` with both buffer and cursor preserved. |
| `encode_fixed_uint_slice`, `encode_fixed_sint_slice` | Under the same width and cursor conditions, write exactly `L` fixed-encoding bytes and advance by `L` on success. | `decode_uint_slice`, `decode_sint_slice` | For `1 ≤ w ≤ type width`, decode a complete in-range prefix starting at the cursor, returning its value and advancing by the consumed length. Width zero for the codec families, widths exceeding the storage type, and cursor positions beyond a writer's buffer are outside the parameterized codec contracts. The concrete 32- and 64-bit array contracts have no input preconditions beyond their Rust types. For a verified slice function, the equality must include the updated cursor and writable slice returned by Aeneas's borrow translation.

## Slice theorem domains and observable state

Let `N` be the storage type's bit width, `w` the const generic argument, `p` the initial cursor, `B` the initial buffer, and `m` its length. The sealed unsigned types are `u8`, `u16`, `u32`, `u64`, and `u128`. The signed writers accept their signed counterparts. The signed decoder additionally requires `From<u8>`, which excludes `i8` and admits `i16`, `i32`, `i64`, and `i128`. Each claim about a primitive instance must identify its type, const-width domain, and the evidence linking the extracted trait operations to that primitive's operations.

For all writers, take `p ≤ m` and `1 ≤ w ≤ N`. Let `E` be the shortest or fixed mathematical encoding specified above, and `k` its length. Whenever the writer copies `c` bytes, the output length stays `m`. For every index `j < m`, the new byte equals `E[j-p]` if `p ≤ j < p+c`, and equals `B[j]` otherwise. On success, `c=k`, the result is `Some(k)`, and the final cursor is `p+k`. On short capacity, the cursor remains `p`, the result is `None`, and `c=m-p` for shortest writers or `c=0` for fixed writers. An input rejected by the value-range guard leaves the entire buffer and cursor unchanged. These statements include a zero-length buffer and a cursor at its end.

* Both unsigned writers have the stated contract for every value of every supported unsigned type throughout this width domain.
* For both signed writers, the intended contract applies to all values at full width and to every representable value at a narrower width. At narrower widths the actual guard accepts precisely the wider interval `[-2^w, 2^w)`. Inputs outside that interval are rejected before any mutation. Inputs in the difference between this interval and the signed field range remain counterexamples to a general rejection guarantee. The shortest writer produces the ordinary shortest encoding of an accepted value, even if the field cannot hold it, subject to the same capacity rule. For a fixed writer, the same fixed-byte formula applies on the accepted domain when the shortest encoding fits within `L` groups; a fixed-width proof must justify that bound before assuming the padding loop terminates.

For either decoder, start with the mathematical suffix at `p`, taking it to be empty when `p ≥ m`. Read at most `L` bytes. On the first terminator return the value and advance to `p+k` exactly when the signed or unsigned value fits. Return `InvalidEncoding` for a value outside that range or a continuation at group `L`. Return `NeedMoreBytes` when the suffix ends earlier with no terminator. Both error outcomes preserve `p`; the input slice is read-only.

* The unsigned decoder's full intended contract applies at `8 ≤ w ≤ N` with `w mod 7 ≠ 0`. The signed decoder checks the initial byte's width too, so its full intended contract applies at `1 ≤ w ≤ N` with `w mod 7 ≠ 0`.
* At positive widths divisible by seven, both decoders correctly consume all complete prefixes with a terminator among the first `L` groups and return `NeedMoreBytes` on strict shorter unterminated suffixes. The release checks for excess bits at shift `w`, one group beyond the allowed final group. The intended immediate rejection of a continuation at group `L` fails, including when the input ends exactly at that continuation.
* At unsigned widths below seven, an empty suffix and any one-byte terminal value fitting the field still have the specified result. The fast path also returns larger terminal values unchanged. The complete arbitrary-input contract cannot hold for those widths.

The unsigned decoder admits an exact release-behavior contract at `7 ≤ w ≤ N`. Allow `G=floor(w/7)+1` groups and check the natural value against `2^w`. Reaching a terminal by group `G` returns the mathematical value and consumed length if in range. An oversized terminal or a continuation at group `G` yields `InvalidEncoding`; exhausting the input strictly before group `G` with no terminal yields `NeedMoreBytes`. Use the same cursor observations as above. When `w` is a multiple of seven this allows one redundant final zero group, preserving the numeric range but changing the accepted length. At smaller widths the first-byte fast path still returns any terminal byte and advances the cursor by one, and an empty suffix still yields `NeedMoreBytes`.

The signed decoder also admits an exact release-behavior contract at every raw width `0 ≤ w ≤ N`. Set `v=w+1` when `w mod 7 = 0`, and `v=w` otherwise. Apply the signed decoding rule above at width `v`, including its maximum length, both error classes and the final cursor. At a multiple of seven, the release checks a last group beginning at shift `w`, and accepts just terminal bytes 0 and 127 there. Those are exactly the properly extended terminal payloads of an extra one-bit group. No supported primitive width is a multiple of seven, so `v ≤ N`. At `w=0` the rule describes a one-bit signed field. This exact contract exposes the difference from the requested-field interpretation at positive multiples of seven. For `w>N` the decoder explicitly asserts the width bound before accessing the input.

### Unsigned widths below seven in the execution model

For `0 ≤ w < 7`, the release's last-group guard tests shift zero. The continuation loop starts at shift seven. A separate exact contract can therefore ignore the nominal field width after the first byte. Let `j` be the next group index, beginning at zero, and start with a mathematical accumulator of zero. If no byte remains, return `NeedMoreBytes` and preserve the original cursor. Otherwise a terminal at `j=0` returns that byte and advances by one. On a readable group with `7*j < N`, add its seven-bit payload times `128^j`, reducing modulo `2^N`. If it terminates, return this value and advance by the total group count; otherwise continue. If a byte exists at a group with `7*j ≥ N`, the model's checked primitive shift fails. This last outcome is an execution-model failure and has no successful Rust error-result or returned cursor. End-of-input is checked before computing the shift. Proofs must instantiate the actual primitive shift and OR dictionaries to establish the applicable result rather than assuming that the malformed input will map to a Rust error variant.

### Signed slice writer operation laws

For the candidate generic theorems let `V(x)` be the mathematical signed value of a stored element and `N` the reported storage width. The primitive laws constrain only operations that the release uses. Converting `-1`, zero and 127 from `i8` gives their integer meanings. Equality and inequality compare `V`. Right-shifting by a count below `N` divides by the corresponding power of two, rounding down. The in-place seven-bit shift divides by 128 the same way. Masking with 127 yields the Euclidean remainder modulo 128. Checked conversion of that remainder to a byte succeeds and preserves its value. The storage value always lies in the signed `N`-bit range. These hypotheses require independent discharge for a claim about a particular Rust primitive.

At `1 ≤ w ≤ N`, a narrower field passes the release guard precisely when `-2^w ≤ V(x) < 2^w`; a full-width field always passes it. For a passing value let `k` be its shortest signed encoding length in unrestricted mathematical integers. The shortest writer's actual contract uses these `k` bytes, including when the guard passed a value outside the intended field range. The fixed writer's all-input success or short-capacity contract holds for every passing value with `k ≤ L`. This includes every value representable in the intended field. If the guard passes, `k > L`, and capacity is at least `L`, the release may attempt to write beyond the capacity it checked.

The intended fixed-width theorem takes the signed field range as its value premise. To derive the required group bound, observe that `w−1 ≤ 7*(L−1)+6` for positive `w`. Thus `2^(w−1) ≤ 64*128^(L−1)`, and any representable field value already fits a signed string of `L` groups. This proof includes the lower endpoint. A separate wider contract can use this larger signed group interval for every value admitted by the release guard. For negative values, extension beyond the shortest signed representation contributes payload 127; for nonnegative values it contributes zero. The continuation bit is determined by the fixed length, including on the final group of the shortest representation if further groups follow.

Three rejection cases admit proofs without invoking the payload conversion. Both writers return `None` without changing the buffer or cursor when the guard fails. After the guard, the shortest writer also returns `None` with unchanged state when the initial cursor is at or beyond the end. At a valid cursor, the fixed writer returns `None` with unchanged state whenever remaining capacity is below `L`. These branch contracts and positive-path generic contracts must be recorded separately from concrete primitive correspondence.

These domains describe candidate mathematical contracts and known exceptions. Audited proofs and counterexamples have separate entries in the coverage ledger. Proving a guard branch or one concrete instantiation supports only its stated inputs. The slice contracts additionally require the final borrowed state returned by the translated function.

## Error traits and associated constants

The release implements `Error::fmt` for `Display` by asking the formatter to write exactly `"need more bytes"` or `"invalid encoding"`, according to the stored variant. Its observable result and formatter state must equal those of the corresponding single `write_str` invocation, including a formatter error from the delegated operation. Under the default `std` feature, the explicit `std::error::Error::source` implementation returns `None` for both variants. Neither contract asserts how a parser selects an error.

The inherited deprecated `cause` likewise has no underlying source. For a call-only Rust wrapper evaluating either method followed by `Option::is_none`, the corresponding observable is exact: for every error the translated wrapper returns `Result.ok true`. A traceable compiler optimization may eliminate the dynamic return type; the proof then applies to this Boolean observation after optimization. The source and feature selection must be recorded, and the inlining evidence must identify the selected method. A direct theorem retaining the original dynamic signature has a separate dependency audit.

For compiler-derived `Clone` and `PartialEq` on the public `Error` and private `InnerError`, cloning preserves the variant and equality agrees with variant identity on every pair. The inherited inequality operation is its Boolean complement. Derived `Debug` on the inner enum writes its Rust variant name. On the outer one-field tuple struct, observations must agree with formatting a debug tuple named `Error` with exactly that inner variant as its sole field, respecting formatter flags and propagating writer failure. `Eq` and the private sealing trait supply no additional user-defined runtime algorithm. For each of the ten primitive implementations of `UInt` or `SInt`, the associated `BITS` constant must equal the primitive width. Inherited standard-library defaults are distinguished from crate-defined and derived bodies. A proof of an inherited method must identify the selected standard-library implementation and model. These are separate obligations from the codec functions.

## Correspondence and trust

A direct theorem about a generated definition relies on source restoration, Rust compilation, Charon extraction, Aeneas translation, and the imported Lean models for scalar arithmetic, shifts, indexing and arrays used by that definition. Bounds, per-byte observations, and lengths must be proved from those models. If a Rust adaptation is used, its relation to the release requires separate evidence. The byte-level contracts separately determine the observable representation and its shortest or fixed length.


For concrete writer instantiations, a target-local support module may translate the payload of a Rust narrowing error into the unit payload used by the pinned Aeneas library. The conversion relation maps `Ok(b)` to `Ok(b)` for the same byte and maps each `Err(kind)` to `Err(())`. The representation of a conversion diagnostic is outside the codec output. Each concrete writer proof must establish that its actual generated conversion returns `Ok(b)` for its masked payload, with the byte equal to that payload. Separate extraction of a dependency such as `max_len` requires a definition forwarding to the selected original body with the same type and semantics. Source identity, regenerated model identity and the authored support-module identity belong to the evidence.
